# Habitat 🌿

A private mini social network for a group of friends. You make a Habitat, invite your people, and build it from **modules** (a feed, photos, events, chat, polls, birthdays and more) that the group chooses together by voting. Nothing is public, there are no ads and no algorithm.

The design is in [`PLAN.md`](./PLAN.md). How to make a module is in [`docs/writing-a-module.md`](./docs/writing-a-module.md).

## What's here

- **Habitats** with owner / admin / member roles, invite links (hashed, expiring, limited), nicknames, leaving with or without your content.
- **A module system.** Every module stores records through one validated, permissioned service, so built-in, JSON-defined and (later) AI-built modules all run on the same rails.
- **Group voting** to add or remove modules, change the voting rule, or change module settings: majority, everyone-agrees or admins-decide.
- **Modules:** Feed, Photos, Events, Chat _(on by default)_; Polls, Birthdays, Recommendations, Wishlist (secret claims), Split Costs, and Bucket List _(a pure-JSON module)_.
- Comments, reactions, @mentions, pinned posts, notifications, email (votes, reminders, weekly digest), reports to admins, data export and account deletion.

## Stack

TypeScript · Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · Radix UI · TanStack Query · PostgreSQL 16 + Drizzle · Better Auth (magic link + Google) · Zod · Vitest · Playwright · Cloudflare R2 (photos) · Ably (realtime, optional) · Resend (email) · Vercel + Neon.

## Run it

Needs Node ≥ 22, pnpm 10 and PostgreSQL 16.

```bash
pnpm install
cp .env.example .env     # set BETTER_AUTH_SECRET (openssl rand -base64 32)
pnpm db:up               # Postgres via Docker (dev :5432, tests :5433); or point DATABASE_URL at any Postgres 16
pnpm db:migrate
pnpm db:seed             # optional: a demo Habitat
pnpm dev                 # http://localhost:3000
```

With `EMAIL_TRANSPORT=console` (the default) sign-in links are printed in the terminal.

**Optional services.** The app runs without them:

| Missing                   | What happens                                                     |
| ------------------------- | ---------------------------------------------------------------- |
| `R2_*`                    | Photo upload is hidden; albums still work                        |
| `ABLY_API_KEY`            | No live updates; chat polls every few seconds                    |
| `GOOGLE_CLIENT_ID/SECRET` | Only the email link is offered                                   |
| `RESEND_API_KEY`          | Use `EMAIL_TRANSPORT=console` locally; production needs `resend` |

## Test it

```bash
pnpm test               # unit: rules, voting maths, queries, module logic
pnpm test:integration   # real Postgres: services, concurrency, isolation between Habitats
pnpm test:e2e           # Playwright, two browsers on a phone viewport
pnpm lint && pnpm typecheck
```

Highlights: voting and invite races (6 simultaneous yes votes install a module once; 5 people racing for the last seat give one success), the **isolation test** that calls every route as a member of another Habitat, hidden wishlist claims, and exact-pennies cost splitting over 1,000 random cases. E2E runs against `next dev` because a production server refuses `EMAIL_TRANSPORT=outbox` on purpose.

## Deploy

1. Neon project → pooled URL in `DATABASE_URL`. 2. R2 bucket (private; CORS allows `PUT` from your URL) and API token. 3. Optional Ably app. 4. Resend domain. 5. Vercel: import the repo, set the variables from `.env.example` (production needs `EMAIL_TRANSPORT=resend` and `CRON_SECRET`), add the Google callback `/api/auth/callback/google`. Migrations run on production deploys via `vercel-build`; `vercel.json` schedules the four cron jobs.

## How it differs from PLAN.md

- UI primitives are hand-written on Radix in `src/components/ui/` rather than generated by the shadcn CLI.
- Ably and Resend are called over REST (`fetch`) from the server; only the browser uses the Ably SDK.
- User ids are Better Auth's text ids (not uuids); everything else is uuid.
- `registry.ts` (server, manifests only) is split from `ui-registry.ts` (React), and `CardFor`/`Timeline` live in `components/` to avoid an import cycle.
- Polls close server-side via a new `lockedAfterParentField`; update scopes gained `member`; fields gained `min`/`minItems`.
- **Not built yet:** Sentry, and the AI module builder (§13 of the plan; MDL is ready for it). Live Ably, R2 and Resend are implemented but untested against the real services.
